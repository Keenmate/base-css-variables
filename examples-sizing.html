Font sizes, spacing, radii and field heights are stored as bare numbers and multiplied by one unit: calc(var(--base-font-size-sm) * var(--base-rem)). pure-admin sets the unit to 10px (its html font size), so 1.4 is 14px. Change --base-rem on any element and everything inside scales together: a compact grid, a roomy dialog.

SZ03 · Breakpoints

--base-breakpoint-mobile and --base-breakpoint-tablet are the widths where layouts switch. @media can't read var(), so they are read from JavaScript (pure-css's config, web-components-core's env.breakpoint); pure-css compiles the same widths from SCSS. Resize the window.

const css = getComputedStyle(document.documentElement);
const mobile = parseFloat(css.getPropertyValue('--base-breakpoint-mobile'));  // 768
const isMobile = matchMedia(`(max-width: ${mobile - 0.02}px)`).matches;

SZ04 · Dropdown offset

--base-dropdown-offset is the gap between a field's bordered box and the panel it opens: a dropdown, a calendar, any anchored popover. Components read it from JavaScript and pass it to web-components-core's positioning as offset, so every panel opens at the same distance. Before 2.0.1 each component hard-coded its own (multiselect 4px, daterangepicker 8px). Plain px, like the breakpoints. The slider sets it on the panels below only.

SZ05 · Touch target

--base-touch-target-min is the smallest a tappable control may be on a touch / coarse-pointer device: option rows, the close / Done button, icon-only buttons in a component's phone presentation. 44px is the Apple HIG minimum and the WCAG 2.5.5 target size. Components use it as a floor, min-height (plus min-width for icon-only controls), inside their phone rules; desktop rows keep the height scale. Plain px, like the breakpoints. The slider sets it on the sheets below only.
