# Base CSS Variables 2.2.0 — Release Notes

**Released:** 2026-11-27 · **Stable** (`npm install @keenmate/base-css-variables`)

These notes cover the changes since **2.1.0**, the last version on npm.

One default changed: `--base-rem` is now `10px` (was `1rem`). In pure-admin nothing changes. On
any other page that loads the contract, components shrink to the size they were designed for.

The exhaustive, per-change list is in
[`CHANGELOG.md`](https://github.com/keenmate/base-css-variables/blob/prod/CHANGELOG.md) (section
2.2.0); this document is the upgrade guide and the highlights.

## Upgrade checklist

**Apps and themes**

- [ ] pure-admin apps: nothing to do. ([details](#base-rem-is-10px))
- [ ] Other pages that load `base-variables.css`: components get smaller (to their intended size).
      If you had set `--base-rem: 10px` yourself to fix that, you can remove it.
      ([details](#base-rem-is-10px))
- [ ] Optional: to follow the browser's font-size setting, set `--base-rem: 0.625rem` (16px root
      only). ([details](#base-rem-is-10px))

**Component authors**

- [ ] Remove the `--base-rem` entry from `contract-check.json`: your `10px` fallback now equals the
      contract default. Bump the devDependency to `^2.2.0`. ([details](#base-rem-is-10px))

## Behaviour changes

### `--base-rem` is 10px

Sizes are unitless multipliers combined as `calc(<multiplier> * var(--base-rem))`, written in 10px
units. `1rem` gave 10px only on a 10px root:

| Page root font size | `1rem` (old) → `1.4` | `10px` (new) → `1.4` |
|---|---|---|
| 10px (pure-admin) | 14px | 14px |
| 14px (e.g. SharePoint) | 19.6px | 14px |
| 16px (browser default) | 22.4px | 14px |

Any rem-based default ties the components to a root size the host page chose for its own reasons,
so the default is px. Scaling still works: set `--base-rem` on a region (density) or on the page.
