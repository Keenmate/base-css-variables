# Base CSS Variables 2.0.2 — Release Notes

**Released:** 2026-11-12 · **Stable** (`npm install @keenmate/base-css-variables`)

These notes cover the changes since **2.0.1**, the last version on npm.

One new token: `--base-touch-target-min` (`44px`), the minimum tap size components use in their
phone / coarse-pointer presentation. Nothing existing changed, so this is a drop-in update.

The exhaustive, per-change list is in
[`CHANGELOG.md`](https://github.com/keenmate/base-css-variables/blob/prod/CHANGELOG.md) (section
2.0.2); this document is the upgrade guide and the highlights.

## Upgrade checklist

**Apps and themes**

- [ ] Nothing required: no token was renamed, removed or re-valued.
- [ ] Optional: set `--base-touch-target-min` (e.g. `48px`) to change every component's tap size
      at once. ([details](#touch-target-size))

**Component authors**

- [ ] In the phone / coarse-pointer presentation, size option rows, the close / Done button and
      icon-only buttons with `min-height` / `min-width: var(--base-touch-target-min, 44px)` —
      rulebook check C-RO-7 expects it. ([details](#touch-target-size))

## New features

### Touch target size

`--base-touch-target-min` is the minimum tappable size on touch devices, `44px` — the Apple HIG minimum and the WCAG 2.5.5
target size. Until now each component chose its own touch sizing, so rows in one app could have
different heights. Components use the token as a floor, not a fixed height, so dense content still
grows:

```css
@media (pointer: coarse) {
  .option { min-height: var(--base-touch-target-min, 44px); }
  .close  { min-width: var(--base-touch-target-min, 44px);
            min-height: var(--base-touch-target-min, 44px); }
}
```

It's plain `px` like the breakpoints and `--base-dropdown-offset`, not a rem multiplier, and it
lives in `:root` (an input), so a theme or a single subtree can override it.
