Text on fills — WCAG 2 vs APCA, and hover / pressed states

A button's text is black or white, whichever contrasts more with its fill. "More" depends on the model: WCAG 2 (the contrast ratio audits check today, pass = 4.5:1) or APCA (the perceptual model being developed for WCAG 3, scored as Lc; about 60 for body-size text, 45 for large or bold text). WCAG 2 is known to favour black on bright saturated colours; APCA usually prefers white there. Every chip shows both scores: wavy = below WCAG 4.5:1, dotted = below APCA Lc 60.

3 · The agreed model — contract colours, button states in each component

The contract supplies only the role colours (--base-<role>-color and --base-on-<role>-text-color, picked by APCA). Each button component has its own state tokens with the agreed defaults: the text stays, the fill moves away from the text on hover / press, the border follows the fill. Two components are shown: a pure-admin button (--pa-btn-<role>-*) and another component's button (--ms-btn-<role>-*). With no overrides they look the same, because both default to the contract. The editor below is a theme: anything you set there applies to the page, like a theme stylesheet.

Try a preset, or write your own declarations: 
/* contract (inputs; text on fill is derived) */
--base-<role>-color
--base-on-<role>-text-color      black / white by APCA

/* each button component's own tokens, defaults: */
--pa-btn-<role>-bg            var(--base-<role>-color)
--pa-btn-<role>-text          var(--base-on-<role>-text-color)
--pa-btn-<role>-bg-hover      bg + 15% of the text's opposite
--pa-btn-<role>-bg-active     bg + 30% of the text's opposite
--pa-btn-<role>-text-hover / -text-active    = text
--pa-btn-<role>-border / -border-hover / -border-active
                               = bg / bg-hover / bg-active
(--ms-btn-<role>-* : the same, in another component)

Section 2: today's step is the contract's --base-<role>-color-hover / -active (15% / 30% black in light mode, white in dark mode); pressed is shown for every role, though the contract defines -active only for primary. Section 3 is the agreed model: those contract steps stay as shared colours, and each button component owns its hover / press tokens. The APCA pick is computed in CSS from APCA's luminance (x2.4 as a polynomial — Firefox doesn't allow pow() on colour channels); it matches exact APCA except where black and white differ by less than 1 Lc.
