Components use only four durations and three easings, all from the contract: snappy rather than animated. Under prefers-reduced-motion: reduce the durations become 0s and scrolling jumps; the one exception is the loader, which slows down instead of stopping (Loader). Turning motion off is CSS only, no attribute.
Every speed reads 0s? Then your system asks for reduced motion (prefers-reduced-motion: reduce), and the contract has turned animation off: that's the feature working, not a bug. The setting lives in Windows: Settings → Accessibility → Visual effects → Animation effects; macOS / iOS: Accessibility → Display / Motion → Reduce motion.

MO01 · Four speeds, and turning motion off

Each lane moves with one duration and the standard easing. In use the speeds are for small changes: hover fills, opening a dropdown, expanding a row.

To turn motion off in an app, set the four durations to 0s, page-wide or on one region. It's CSS only, no attribute; a component also takes its own --<prefix>-transition-*: 0s. The checkbox does it for the demo below.

/* Motion off for the whole app (or put it on one region) */
:root {
  --base-duration-fast: 0s;
  --base-duration-normal: 0s;
  --base-duration-medium: 0s;
  --base-duration-slow: 0s;
}

MO02 · Three easings

Same distance and duration (slowed to 1s here so the curve is visible). Under reduced motion they are 0s as well, unless the switch at the top is on. standard for moves within the page, out for things entering (a dropdown opening), in for things leaving.

MO03 · Scroll behaviour

--base-scroll-behavior is smooth, and auto (a jump) under reduced motion. Use it as CSS scroll-behavior or pass it to scrollTo / scrollIntoView, as the buttons do.

const behavior = getComputedStyle(list).getPropertyValue('--base-scroll-behavior').trim();
row.scrollIntoView({ block: 'nearest', behavior });
