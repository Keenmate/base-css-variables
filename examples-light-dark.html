Every colour that differs between modes is written once, as light-dark(light, dark). The browser picks a side from color-scheme: the contract sets light dark on :root (follow the OS), and [data-theme="light"] / [data-theme="dark"] force one mode on any element and everything inside it, shadow roots included. There are no separate dark-mode tokens and no .dark class to keep in sync.

LD01 · Which mode is on

The page follows your OS until you use the theme switch (top right), which sets data-theme on <html>. Both values of each input below are rendered side by side; the one in use is outlined.

TokenLightDark

Sizes, spacing, durations, z-index, icons and the palette are the same in both modes: plain values, no light-dark().

LD02 · Forcing a mode on one region

A dark sidebar in a light app, or a light preview inside a dark editor: data-theme on the region. The derived tokens are recalculated there too, so hover steps, tints and text levels match the forced mode, and plain CSS inside follows.

Keenmate components detect the page theme (data-theme on <html> / <body>, via web-components-core) and that signal wins over the region's. Inside a forced region, give each component the region's mode too: <web-multiselect data-theme="dark">. The multiselects below do.

data-theme="dark"

data-theme="light"

<aside data-theme="dark">                      <!-- always dark -->
  <web-multiselect data-theme="dark"></web-multiselect>
</aside>
<section data-theme="light"> … </section> <!-- always light -->
