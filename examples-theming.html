A theme sets a handful of inputs: the primary colour, the page and main surfaces, the text colour. Every other token (hover and pressed steps, tints, text levels, borders, text on fills, item states) is a formula over them. Set the inputs once and pure-admin, every Keenmate component and this page's own chrome follow. Light / dark: the theme switch (top right).

TH01 · One theme, everything follows

Pick a theme or a primary colour. It is written to :root as inline custom properties, the same as a theme stylesheet would set them. The mock app (plain CSS), the two real components and the page around them (header, chapter nav, cards) all re-theme together.

TH02 · Inputs in, derived out

The tokens below are computed now, on :root. The ones marked input come from the theme; the rest are formulas in base-variables.css (color-mix() and OKLCH relative colours) and change with them. A theme never sets a derived token; to retune one step for one component, override that component's own token instead.

TH03 · Theming one part of a page

A second theme for one region: a dialog, a sidebar, an embedded widget. The derived tokens are calculated where they are declared, on :root, [data-theme] and .base-scope. Setting an input on any other element only changes that input, and every formula keeps the page's value. Put the class on the element that sets the inputs.
